# 大书分批提取执行手册（8批×5路实战版）

> 来源：2026-10《Python Cookbook》40块/8批/30+子代理实战（1000+ 候选，全部通过逐字校验）。适用：块数 >20、需要多批子代理并行提取的书。

## 架构

- 40 块 → 8 批（每批 5 块）× 5 路（框架/原则/案例/反例/术语）。
- 每批一次 delegate_task 派 5 个子代理并行（上限 6，留 1 给主线）；**批间串行**（下一批读上一批追加后的文件）。
- 每个子代理指令的九要素：提取器路径 / 本批块清单 / 逐块不能跳 / 输出文件（追加式）/ 逐块回执 / 格式照提取器 / 临时脚本前缀（bN）+ work 目录 / 路径含中文按原样用 / 工具预算。
- **重派单路与下一批写同一文件时必须串行**：重做批 N 的某一路时，下一批同路子代理不能再并发启动——两个子代理写同一个候选文件必冲突（一方触发覆盖保护拒写、或互相覆盖）。先把重做路跑完，再补派下一批缺的那一路；并行预算优先给不同文件的批。

## 子代理一次成型流程（预算 15 次工具调用）

1. 读提取器定义（references/extractor-*.md）；
2. 一次 python `read()` 整读 5 块入内存并打印总览（块名＋字数＋首行即可，**别整块打印**——5 块全文会撞单次输出上限、被迫拆成多轮读取）——**禁用 read_file 分页**（块大的书分页读 5 块要 11+ 次调用，预算在「读」这一步就烧光）。这条必须单列进每个子代理的任务描述：子代理看不到本手册，只写在手册里没用；
3. 构造候选数据表并**先落成 work/ 构建脚本**（数据+逐字断言+写盘+回读复核一体，**默认一口气跑完：校验通过即自动写盘**）：摘录写入前 assert「逐字存在于对应块」。三条落盘纪律：①「先干跑校验、再另起一次调用写盘」是禁忌——多路实测把校验跑完却没写盘就触顶，整批重做；check-only 模式只留给组长调试。②写盘优先于构造完美：宁可条目略少也要尽快入库；超大块批（5 块合计 >8 万字符）按块分段构造、每 2-3 块增量写盘一次——半批入库待补，好过全批留在上下文里等最后一次写。③数据先成文件时，触顶最坏是「脚本就绪没跑完」，组长一条命令收尾；
4. 渲染写入（候选插在回执区之前；回执追加本批 5 行）；
5. 重新解析文件核对条数。

回收触顶子代理按产物分诊：①有就绪脚本/数据 → 组长直接跑通＋补漏（先跑脚本的 check 模式复验锚点，个别仍失败的按它打印的定位改一两条再 write）；②无脚本无数据 → **只重派该路**（别整批重来），并把上一轮探测结论（块→章映射、已定位的锚点修法表）附进新任务描述，别让新子代理从零摸索。

实测：不做「一次成型」的子代理会触顶预算停在 85-95%，需要组长人工收尾（占时 20-40%）。从第 2 批起把本流程与上批踩坑写进 context，产线明显变稳（第 5 批零返工）。

## 块文件与摘录纪律（最重要）

- 块文件是 CRLF：读入先 `.replace('\r\n','\n')`。
- read_file 显示的行号会因折行重排，**不可**当源码行号；要定位原文写 python 在字符串上 find/切片。
- 摘录锚点优先「整行」（物理行），避免跨折行短语（会被折行拆字导致锚点失配，如「日期/而是」被拆开）。
- **摘录不得含 `[第N页]` 页码标记**：句跨页时标记插在句中——取紧邻的不跨页子句；写入前 assert 双检查（逐字存在 + 不含「[第」）。
- Python 脚本里含单引号的文本外层用双引号（多次翻车点）。
- 英文折行处可能缺空格，必要时用「折行处补空格」变体定位。
- **锚点失配最高频的原因是「与原文差一字」**：同义改写（「若」写成「假如」）、漏词（「描述了」写成「描述」、「努力说服」抄成「说服」）、语序（「按一定的先后顺序」写成「按一定的顺序」）——修法是换更短的唯一子串重试，不要反复试长句；「长句全对才过」的洁癖会烧光预算。

- **摘录默认用「锚点定位 → 从原文切片」生产，不手抄**：手抄长摘录的批次级错率可达三成（实测一批 151 条错 47 条），错的全是肉眼不可辨的细微差异（差一字、漏词、全角「－」抄成半角「-」）。**已写错摘录的批量救回配方**：写一个 norm2raw——按字符遍历块文本，跳过 `[第N页]` 与空白，同时记录「归一化字符 → 原文索引」映射；`norm(锚点)` 在归一化流中命中后，用映射反查出**原文真实片段**回填（天然逐字、跨折行也成立）。锚点逐级截短重试（整句 → 前 24/20/16/13/10/8 字符），只把真定位不到的个别条目留给人工——别让个位数失败条目卡住整批写盘。

- **校验失败默认改摘录、不改校验口径**：归一化只容忍空白、换行与 `[第N页]`；全半角标点、字形差异（「12－60」vs「12-60」、「若」vs「假如」）算真差异——修法是把摘录对齐原文，不是放宽校验器（放宽会让整批“看似全绿”地带着错字交付）。唯一的例外通道：**跨页摘录的页眉噪声行**——摘录本身干净（不含 `[第`）、内容真实，只是跨页处原文在页边界插入了页眉行（页码数字行、`N.M 小节名`式页眉行），严格匹配必失败；全量校验器对此给二次机会（按行剥离「页标记行／纯 1–3 位页码行／行首 `N.M` 小节式页眉行」后重试，已做进 `scripts/verify_candidates.py`），这类摘录原样保留、不必重写。
- OCR 转出的文字层书常有**纵向重影**（同一句重复 3–4 个物理行）：摘录一律取**单行或单行前缀**（前缀=从行首到行内任意位置的连续片段，截到半句也没关系，逐字即可）——**跨行摘录在重影块必失败**：重复行插在两行之间，原句两半不再连续（修法：换成已验证的单行前缀）；整段重影抄进摘录同样不合格；不要先"清洗重影"再提取——写坏正文的风险大于收益。
- **去重只用于阅读，锚点必须回原始块**：把重影折叠成去重版读着舒服，但别从去重版抄锚点——它的断行点与原文不一致（原文在页标记等处断行不同），照抄会出「看似在、实际不连续」的假匹配；摘录写入前一律对**原始块文本** assert。

## 追加式多批写入

- 候选一律插在「## 逐块回执」区之前；回执按块**追加**行（旧行不动）。
- 跨块小节（如 6.13 跨 block12-13）：位置写「第 12-13 块」，回执数按**摘录来源块**归（与校验器口径一致，否则 mismatch）。
- 反例路编号跨批连续（001→242→…），每批加「## 反例候选（第 N 批…）」段。
- 带结构约定的文件（案例路「### 第 N 块」分段标题等）：初建批次定下的结构，续写批次常不照写——派发时把「保持文件现有结构（分段标题、字段格式）」写进任务描述，收尾时按下方收尾清单补回缺失。
- 写回一律 `open(p,'w',encoding='utf-8',newline='')`：Windows 文本模式会把换行符转成 CRLF，一次追加就能改掉已入库的整文件行尾（实际翻车：写盘后全文被转 CRLF，靠备份还原）。把这行直接写进每个追加任务的描述。
- **各候选文件的回执区结构会随批次漂移**：有的文件每批追加「## 逐块回执（批次 bN）…」独立段，有的只有单段标题、下按块累加行——新批追加前先读文件现状、按现状模式续写；任务描述写「先读回执区结构再决定追加方式」，别在指令里写死一种模式。

## 组长收尾与独立校验

- 子代理自报 ≠ 完成：边跑边抽查产物，收尾时逐个跑**独立校验脚本**（技能第 4 步）——解析全文件、逐条摘录回块比对（直接子串失败 → 去空白归一化重试，覆盖折行）、回执区一致性，再加一道**回执区块号覆盖审计**（五路各自 1..总块数 每块至少一行；缺号＝某批漏做或漏写回执——实测一整批案例路因拆出串行后遗忘，靠此审计找回）。被拆出串行的路（重做/延后）派发前先记 `状态.md`「待补派」台账、收尾销账。
- 常见尾巴及修法：
  - 锚点跨行失配 → 改锚点（用右半段/整行）重跑；
  - 渲染脚本语法错（未转义引号）→ 数据从 transcript 不可完整恢复时直接换人重做（单任务、预算全给）；
  - 脚本语句顺序错（UnboundLocalError：EOL 探测、新段拼接用的变量被写在读文件之前）→ 组长按执行顺序通读、把语句调到依赖之后重跑，别重派；
  - 写回换行符断言（文件混合换行）→ 归一化 LF 写回；
  - 位置写跨块范围「第 X-Y 块」→ 校验器要支持范围+多块候选；
  - 空摘录条目（`- 原文摘录：` 后是空围栏）→ 收尾脚本统计「摘录为空」的条目数，非 0 就地从块文件补一条单行完整句（拖到第 4 步才暴露等于整包延期）；
- 子代理报「假匹配已定位、正确锚点已算好、只差替换」或它的修脚本被合并断言短路 → 组长直接代改：python 解析定位假摘录、精确替换为已验证的单行锚点、重跑全量校验；修这类脚本每条独立断言，勿用 `and` 串（一条 count=0 会短路掉后面全部替换）；
- 代改替换串先做 `count == 1` 断言，不满足时升级匹配口径：count > 1 说明同一句话在同条目的其它字段（「为什么错」「关联」）也被引用过——用「位置行＋摘录行」的连续片段做唯一替换（或带上 `- 原文摘录：` 字段标签）；count == 0 说明报告里的写法与磁盘实际不符（引号/空格差异），先 repr 看盘上原文再构造。用 grep 普查 `[第` 残留做审计时，先排除文件头部的说明性文字——候选文件开头常有一句“本文件摘录不含 [第N页] 标记”，会被当成残留误报；
- 重跑修复后的写盘脚本前先加**幂等门**（如 `assert '第 26 块：找到' not in s, 'already applied?'`）：断言修好后脚本可能被跑两遍，双跑会把整批条目重复追加；跑完用「新编号连续 + 回执段数 + 全部摘录回块复核」三项收口。
  - 回执数字与校验器计数不一致 → 以校验器「按摘录来源块」的计数为准修回执（子代理可能在回执里把边界条算给邻块，连它自己写的「原文位置」声明都不符）；
  - 候选文件分段结构缺失（如案例路整批没写「### 第 N 块」标题、被校验器整批归到上一块）→ 校验器按摘录在全库实际命中的块做归属，按命中边界补回标题（标题页范围取块文件首尾 `[第N页]`）；
  - 历史批次遗留页标记（摘录里夹 `[第N页]`）→ 删标记行与升级校验器归一化必须同步做：归一化在两侧同时 `re.sub(r'\[第\d+页\]', '', s)`，否则刚清完就整批校验失败；改完立即重跑校验器确认归零。
- 子代理脚本的复核断言要先审再用，四类都实测卡死过收尾：①恒真死代码（`assert x or True`）等于没验；②对构造结果必然不成立的检查（`assert old in new`，而 new 是 old 中间插了内容的拼接）必挂；③越改越长的状态元组（中途塞字段后索引错位）；④**自编词断言**——脚本要求文件里存在某个“子代理以为该有”的词（实测有脚本断言文件含「框架名称」，全库根本没这个词），断言永远失败、写盘永远到不了；而它的总结还会拿「文件由 A 增至 B 字节、写入时间戳 HH:MM」当已写入证据——那实际是 mtime 与字符数的混淆，文件一个字节没动。审断言速判：每条 assert 引用的新字面量先 grep 验证存在再让它跑；修断言用独立条件（`startswith`/`endswith`/数回执段数/数条目数），逐条独立不 `and` 串。核实「已写入」声明：grep 其声称的新条目编号（如 `^## 200\.`）与回执段数，0 命中即未写入，别信字节数。
- 校验脚本自身的坑：`re.S` 丢 `re.M` 会让 `^` 只匹配串首（曾致全文件误报「字段缺失」）；行级比对「整行相等」过严，改「行子串」；五路摘录格式不一 + 位置字段两种写法——直接用本技能自带 `scripts/verify_candidates.py <工作区>`，勿重写。
- **案例路在目录型章节录取量天然稀少**：手法清单、检查表、索引/附录这些区段只有教学性合成代码，没有「人物—动作—结果」，案例路如实记少或 0、不凑数；要收录合成范例得先改 `extractor-case.md` 的收录定义，别在收尾时顺手放水。

## 实测节奏

- 每批 ~4-7 分钟（5 路并行）；8 批一晚可跑完。单批成本可控（flash 模型），主要成本是重试与收尾。
- 多本书排队（用户一次授权蒸多本）时全书串行：一本书的批队列跑完再开下一本，中途无需人工；实测一夜可推进 12-16 批（约两到三本书的提取阶段）。OCR 与云端批队列并行不冲突（OCR 限 2 进程，见 SKILL.md 负载纪律）；某本的 OCR 完成当夜就切块＋写骨架，把提取队列排满，别让流水线空转。
