# 引文逐字校验 —— 口径与坑集（全量）

> 摘自 `SKILL.md`（2026-10-14 下沉，原样迁移）。主文件「第 3 步」保留核心纪律与脚本入口；本文件是校验的全口径与历史踩坑（脚本级为主，出问题时查）。大书批处理执行手册另见 `batch-extraction-playbook.md`。

### 引文逐字校验（必做）

逐块回执只能证明"走了这几块"，不能证明"引文抄对了"。子 Agent 手打摘录有三种高频错误：漏字、删词、标点被替换（弯引号变直引号、破折号变短横）。回执发现不了它们，必须程序化核对。

每一步收尾时对候选跑一次逐字校验：把每条「原文摘录」回到块文件的**原始字节**里做子串比对；不命中的列出清单，让子 Agent 按原文修正后复验；修正不动的在 `状态.md` 记一笔。校验脚本参照各工作区 `work/verify_quotes.py`。**空摘录要单独统计**——空字符串是任何文本的子串，子串比对会放它过去；检查脚本里加一行「摘录为空」计数，非 0 就从块文件补一条单行完整句。

**逐字命中与块号归属是两件事，分开对账。** 子串比对只能证明"这句话在这份材料里"——脚本在任意一块命中就算过，块号错标（第 12 块的内容标成第 13 块）会整批穿过去。历次抽查，出错最多的是块号，不是摘录。收尾时加一道块号自洽检查：解析每条的「原文位置」块号，再找出该摘录实际命中在哪些块，两者对不上的列出修正；派发任务时就把“块号归属务必用脚本逐条核对”写进要求。

**节主体与摘录分属两块时，归属以摘录来源为准。** 例如某节的讨论段被切到了下一块：位置字段写摘录来源块的块号、括号注明主体块（“讨论段在第 N 块”），回执计数也按摘录来源块记——校验器与回执两边同一口径，才不会互相对不上。校验器侧相应允许位置字段声明多个块号（含范围写法如「第 12-13 块」——按范围展开逐块试，命中任一即过），不要只取第一个块号硬对。

**修正子代理产物时，先读磁盘实际文件再写替换条件。** 报告里引用的格式（如“第 13 块”带空格）和文件里的实际格式（如“第13块”无空格）经常不一致，按报告写的替换规则会静默零匹配；替换后立即复核改了几处、以及标注分布与回执段是否对账一致。

**用 patch 工具改含转义序列的脚本行，很容易把文件写坏。** 字面 `\r\n` 这类序列经过写入层会被解析成真控制字符（结果：未闭合字符串、语法错误）。修这类文件改用 python 脚本：需要的反斜杠、换行一律用 `chr(92)` / `chr(10)` 拼接构造，或先 `\r\n→\n` 归一化再按行级替换；改完立刻重跑该脚本验证，不要用肉眼确认。

**追加写回的脚本不要断言“文件必须是纯 CRLF/LF”。** 多批追加后文件的换行常是混合状态（各批写回方式不同），断言必挂。读入统一 `.replace('\r\n','\n')` 归一化、写回统一 LF 即可（写回用 `open(p,'w',encoding='utf-8',newline='')`——Windows 文本模式会把换行符转成 CRLF，一次追加就能改掉整文件行尾）；把“统一换行”当处理前提，而不是当文件事实。

**陷阱：read_file 不是字节保真的。** 它对空白、空行、部分标点有归一化——子 Agent 按 read_file 显示的内容抄引文，会在肉眼看不见的空白差异上翻车。引文提取与修复一律以块文件的原始字节为准；最稳的做法是用脚本从块文件按起止锚点直接切出引文字符串再写入候选，全程不经过手打。

**锚点切引文的两个坑。** ① read_file 的显示行号会因折行重排、不能当源码行号用；PDF 提取还会把行尾的字拆到下一行开头（锚点写“日期减去”，原文实际是“日”＋换行＋“期减去”）。精确引用只能靠脚本在内存字符串上按“去掉所有空白后逐字一致”匹配锚点，别拿行号、也别拿裸锚点直接子串硬碰；② 块文件常带 CRLF，读入后先 `.replace('\r\n','\n')` 再比对（行号不变），拼错换行会整批落空。锚点一律优先选物理整行（整行永不跨行拆字）；必须截短语时避开折行边界。

**摘录不得含 `[第N页]` 页码标记。** 块内页标记是独立行，但跨页的句子会把它夹在句子中间（“……。[第158页]下一句……”）；凡摘录含 `[第` 一律判不合格——选句时避开跨页段落，只取紧邻的不跨页子句。构建脚本里把「逐字存在」与「不含 `[第`」作为双 assert 一起卡（有工作区因此整批返修）。

**构建候选的 python 脚本，含单引号的文本（如 'OPEN'、'Dave'）外层一律用双引号。** 单引号未转义写死脚本是最高发的脚本级失败；脚本写完先过语法检查（如用 ast 解析一遍源码）再执行。

**校验脚本报“全灭”先怀疑脚本本身。** 正则同时带 `^` 行首锚与跨行 `.*?` 时，flags 必须 `re.S | re.M`——只写 `re.S` 会让 `^` 只匹配整个字符串的开头，全部条目被误报“字段缺失”。定位这类问题用 `repr()` 和逐字符 hex 打印可疑区段，不要盯着源码猜。五路收尾的校验脚本直接用本技能自带的参数化版本 `scripts/verify_candidates.py <工作区路径>`，别每路都让子代理自产一个——自产的出过 flags、锚点、匹配口径三类问题。它内置几组易错口径：**摘录三级回退提取**（代码围栏 → `> ` 引用块 → 同行并剥外层中文引号）——五路落盘格式未必统一，写死单一格式会让案例/术语整路误报「缺字段」；**位置字段多写法**（「第 N 块」「块 N」「第 N-M 块」都收）；**空摘录判失败**（漏判则整路假全绿——空串是任何文本的子串）；**跨页噪声行二次机会**（严格匹配失败后按行剥离页眉噪声行重试——跨页摘录原样保留、不误报，全半角差异仍按真差异修摘录）。比对一律**两侧同口径归一化**——只归一化原文一侧会双向出错：不含空格的短锚点「假通过」、跨折行锚点「假失败」，都出过整批级误判。**校验器按“跨批全量”设计**（第 2 批起文件里有多批内容）：回执区按段拼接后核对（`'\n'.join(text.split('## 逐块回执')[1:])`，别只取最后一段）；块号正则用 `(\d+)` 而非 `(\d)`——多位数块号（如“第 10 块”）会被单数字正则静默漏掉；位置字段允许含多个块号；行级校验用子串（`any(exs in ln for ln in lines)`）而非整行相等——摘录常是行内片段，整行相等会把对的判错。
